# Design decisions (and requirements that needed interpretation)

1. **Single lab room = exclusive booking.** Two approved bookings can never overlap (enforced by a DB exclusion constraint). Computers and equipment are then a *capacity* check inside the booked slot. If the lab is ever split into independently bookable rooms, add a `roomId` to `LabBooking` and include it in the constraint.
2. **Permissions as code.** The role→permission matrix is a constant (typed, tested, reviewed). The Roles tab is read-only. A runtime permission editor can be added later; it was not built because it makes security regressions silent.
3. **Reservations without status drift.** Approved bookings hold concrete assets (`BookingResource.reserved = true`) for a *time window*. Asset status `RESERVED` is not set permanently (it would block lending outside the slot); the dashboard "Reserved" figure counts assets with a current/upcoming reservation, and loans/bookings check reservations by time overlap.
4. **Receiver on a loan** = the staff member who receives the equipment back. The borrower is the requester; the issuer is the staff member who hands it over.
5. **Quantity tracking.** Single units are individual assets; cables/adapters are one asset line with a quantity (`isConsumable`).
6. **Refresh tokens** are opaque random strings stored hashed and rotated on every use; reuse of a revoked token revokes all sessions of that user. They live in an httpOnly, SameSite=Lax cookie scoped to `/api/auth`. `JWT_REFRESH_SECRET` is present in `.env.example` for operators who later switch to signed refresh tokens; it is not used today.
7. **Audit tamper resistance** is layered: DB triggers block UPDATE/DELETE/TRUNCATE; each row stores `hash = SHA-256(prevHash + content)`, and `GET /audit/verify` recomputes the chain. A superuser with direct DB ownership can still disable triggers — protect DB credentials and back up off-host. Audit rows are written inside the same transaction as the business change.
8. **Time.** All timestamps are UTC; the lab-local zone (`LAB_TIMEZONE`, default Asia/Colombo) is used for opening hours and for the UI. Sri Lanka has no DST.
9. **Migrations.** The initial SQL migration was generated from `schema.prisma` by `database/tools/generate_init_migration.py` (not by `prisma migrate dev`) because it was authored in an environment without network access. See README → Troubleshooting if `prisma migrate deploy` reports drift.
10. **Email notifications** are not implemented; every notification is stored with an `emailedAt` column and created through one service, so a mailer can be added in `NotificationsService.notify` without touching callers. (Listed as an optional future feature in the requirements.)
11. **Photos/documents** are stored on a local volume (`UPLOAD_DIR`) with random file names, type whitelist and 5 MB limit; swap for S3-compatible storage if the deployment is multi-node.
